Chuleta Docker: te guío desde el enunciado hasta el comando

Método para CUALQUIER ejercicio de Docker (5 preguntas):
  1. ¿Qué imagen base y con qué tag exacto? FROM nginx:1.27-alpine, httpd:2.4.62, python:3.15…
  2. ¿Qué instalo o copio? RUN con el gestor de paquetes (apk en Alpine, apt-get en Debian) y COPY a la ruta del servidor.
  3. ¿Cómo se llaman la imagen y el contenedor? <usuari>/nom:tag y --name tal cual los pide el enunciado.
  4. ¿Qué puerto publico? -p PUERTO_MÁQUINA:80 (el interno es siempre 80).
  5. ¿Cómo compruebo y qué entrego? curl o docker exec; después docker push y GitHub.

⚖️ Cosas parecidas: ¿cuál uso?
OpciónDiferencia
VM / Docker: aislamiento y SOVM: aislamiento a nivel de hardware, un SO independiente cada una. Docker: aislamiento a nivel de SO, los contenedores comparten SO.
VM / Docker: arranque y tamañoVM: minutos y pocos GB. Docker: segundos y KB/MB.
VM / Docker: crear y moverVM: crearla lleva más tiempo y se puede mover a otro host. Docker: se crea en segundos y se destruye y recrea en vez de moverse.
VM / Docker: recursos y disponibilidadVM: más recursos; difícil encontrarlas ya preparadas. Docker: menos recursos; contenedores prediseñados fácilmente disponibles.
-t / -y-t etiqueta la imagen en docker build. -y es de apt-get install -y: no existe en docker build.
docker tag / docker buildtag añade otro nombre a una imagen ya hecha (arregla el usuario mal). build la reconstruye.
--no-cache / docker builder prune--no-cache reconstruye todas las capas (error «parent snapshot not found»). builder prune limpia la caché de build (fuera de los apuntes).
CMD / ENTRYPOINTENTRYPOINT se ejecuta primero; CMD da los parámetros por defecto (y solo cuenta el último CMD).
COPY / ADDCOPY copia del contexto. ADD igual, pero admite URL: se recomienda COPY.
RUN / CMDRUN se ejecuta al construir la imagen. CMD al arrancar el contenedor.
EXPOSE / -pEXPOSE solo documenta el puerto. -p host:contenedor lo publica de verdad.
ARG / ENVARG existe al construir (--build-arg). ENV queda en la imagen y en el contenedor (-e).
docker rm / docker rmirm borra contenedores. rmi borra imágenes (sin contenedores que las usen).
docker exec / docker attachexec ejecuta un comando nuevo dentro. attach se engancha al proceso principal.
docker images / docker psimages lista imágenes. ps lista contenedores (-a incluye los parados).
docker build / docker commitbuild crea la imagen desde un Dockerfile. commit la crea desde un contenedor.
Volumen anónimo / con nombre / montadoAnónimo: -v /data. Con nombre: -v vol1:/data. Montado: -v /ruta/host:/ruta/contenedor.
Alpine / DebianAlpine: apk add --no-cache; imagen pequeña. Debian: apt-get update + install -y; más pesada.
-p 8081:80Izquierda = puerto de tu máquina. Derecha = puerto del contenedor (80 en nginx/httpd).
